# 交通指标说明

主页使用三项直接可读的交通指标，数值越低越好。正常视觉仍为S1、冻结工程固定配时、YOLO+MP三方，特殊视觉仍只比较S1与YOLO+MP。正式评测覆盖范围没有因展示只选十字路口而删减。

## 平均每车等待时间

单位：秒/车。对每辆正式评测车辆，累计路网内因交通停驶的等待，再加上计划出发后因入口拥堵而无法入网的等待，最后除以正式车辆数。

停车等待采用SUMO的`waitingTime`，不把正常行驶时间算作等待；入网等待采用实际出发时间与计划出发时间之差。到评估截止仍未能入网的车辆，计入从计划出发到截止时刻的入网等待，不能把这些最拥堵的车辆删除。[SUMO行程输出定义](https://sumo.dlr.de/docs/Simulation/Output/TripInfo.html)

## 平均排队长度

单位：辆，不是米。先统计该路口全部受信号控制的进口车道中，速度低于0.1米/秒的车辆总数，再对共同发车窗口98—398秒做时间平均。车道去重，避免同一车道因多个信号连接重复计数。它不是一个方向的队列，也不是某一帧的最大排队；尚未进入路网的车辆不计入这项物理队列统计。[SUMO车道停车数定义](https://sumo.dlr.de/docs/TraCI/Lane_Value_Retrieval.html)

多案例汇总时，每个案例使用相同的300秒观察窗，再对案例均值取平均；不要按不同控制器的提前结束时间改变分母。

## 平均每车行程时间

单位：秒/车。每车从计划出发到到达目的地计时，包含入口拥堵导致的延迟。南沙评估截止1298秒，Town截止518秒；未完成车辆计入截至截止时刻已经累计的耗时。这是有限时域均值，不宣称全部车辆已完成完整行程。

跨案例按正式车辆数加权。原始南沙记录是案例均值，先乘回该案例车辆数；原始Town记录是总行程，直接求和；最后均除以相应车辆总数。旧主页把案例指标相加，现改为按车辆归一化的常用指标，原始结果文件没有修改。

## 数据来源与补测

- 原批次仍为`unified-visual-20261028`及`fusion-pilot-20261029`，没有重训或切换旧权重。
- 对271个保留了动作/灯态、或可由冻结工程表确定灯态的回合，纯SUMO重放原控制序列，并逐案例核对原行程结果，全部匹配后才纳入新增等待、排队统计。重放不调用视觉模型，不生成新的模型决策。
- 南沙正常视觉YOLO+MP原72回合缺失动作/灯态历史，无法根据一个行程汇总值恢复等待和排队。用户已于2026-10-30批准只补跑这72个对照；使用同一计划、种子、正常机位、冻结画线及原控制规则，保存完整动作/灯态后核对重放行程。
- 仅在72回合全部成功后，YOLO+MP的等待、排队及行程整行切换至同一新批次`nansha-mp-metrics-20261030`。原始109.36秒/车属于缺日志的旧批次，不与新等待、排队混拼；S1和工程固定记录不重跑、不替换。
- 补测逐案例原始成绩与完整日志归档入口随`results/nansha-mp-metrics-2026-10-30.json`一同发布；截至全部齐备前，主页仍保留“未记录”，不拿未完成子集冒充72案例全量。
- [`fusion-2026-10-30-traffic.json`](../results/fusion-2026-10-30-traffic.json)保留逐案例来源状态、原行程与重放行程、停车等待总量、入网等待、车辆数、排队均值和统计窗口。
- [`fusion-2026-10-30-traffic.csv`](../results/fusion-2026-10-30-traffic.csv)是主页三项指标的直接汇总。

## 动图中的实时指标

动图展示的是实际摄像头输入、实时指标与最近一次真实决策，不是整批结果表的动画。

实时平均等待为截至当前已进入车辆的累计停车等待总量，除以已进入车辆数，包含已离开的车辆和共有预热车辆；不把尚未入网车辆的等待混入这个动态计数。实时排队为当前路网停车车辆数。两项均由原录制灯态重放获得，并与901个录像时刻的排队、在网数和累计到达数逐帧核对。因此它与主表“正式车辆＋含入网等待”的口径不同，不能将动态图中的某一时刻数值代入整批表。

决策面板只读取该次回合真实保存的动作、决策时刻和推理耗时；没有记录的概率、推理理由或置信度不补造。5倍速播放只改变展示速度，不改变交通仿真、模型输入或决策。
